# スキル

スキルは .claude/skills/スキル名/SKILL.md で定義する。
/スキル名 で呼び出し、必要に応じて議題や追加条件を指定する。
※ 実際の動作には、Claude Codeによるエージェントの呼び出しが必要。

## multi-perspective

議論系の3エージェント（realist / idealist / critic）に独立した分析を依頼し、
意見の比較と最終結論の作成を行う。調査系エージェントは呼び出さない。

使い方：/multi-perspective 議題

## setup-ai-team

AI組織の構築、エージェントの追加、役割や指示の改善を支援する。
作業前に変更内容を説明し、承認を得てからファイルを作成・変更する。

使い方：/setup-ai-team 追加したい役割や改善したい点

## research-it-news

IT・セキュリティの最新ニュースを、SKILL.md 内の情報源リストから集める。
research-collector で収集し、research-checker で出典・日付・整合性を裏取りして要約する。
手動で呼んだときだけ動く。定期実行はしない。

使い方：/research-it-news [期間] [テーマ・影響の前提]

- 既定の期間：直近1週間
- 既定のテーマ：セキュリティ中心（インシデント、脆弱性、注意喚起）＋クラウド・IT全般
- 影響の前提：指定した利用環境・業務に合わせて、影響の大きい順に並べる

出力

- outputs/research/yyyymmdd_it-news/topic_summary.md
- 結論、使用したエージェント、根拠、参考サイトを載せる
- 「確認済み」と「未確認・続報待ち」を分けて書く
- 各項目に「重要度」（高・中・低）と「カテゴリ」（脆弱性・インシデント・クラウド・その他）を付ける。ビューアの記事風の表示でタグとして使う
- 過去の outputs/research/*_it-news/ を確認し、掲載済みの項目は重複して載せない

項目数と処理の重さ（トークン・時間）

- 項目数の上限は10件（仮）。引数で変更できる。超えた分は、影響の大きい順に残す。
- 裏取りは項目数に比例して重くなる。上位10件程度は一次情報まで確認し、下位は出典と日付の確認までにする。
- 実績の目安：26項目で、エージェント合計が約30万トークン、所要は10分前後。
- 検証担当（research-checker）は上位モデル指定のため、同じトークン数でも単価が高い。

取得できない情報源の扱い

- 全情報源を試し、取得結果（できた / できなかった / 一部のみ）を成果物に書く。
- JavaScript で描画されるページや、アクセスを拒否（403）するサイトは、取得できないことがある。
  「更新なし」とは扱わない。
- 取得ツールが失敗したら curl で再試行する。拒否されたサイトは回避しない。
- RSS や API など、負荷の軽い公式の公開形式を優先する（情報源として追加する場合は、実在確認後に利用者が確定する）。

相手サーバーへの配慮

- 同じサイトへの連続・並列アクセスを避け、必要最小限にする。
- 情報源を追加するときは、robots.txt と利用規約を確認する。
- 定期実行はしない。呼んだときだけ動く。

情報源リスト

- 公的機関、脆弱性情報、ベンダー公式、ITニュースサイトを SKILL.md 内に持つ。
- 現在は暫定リスト。URLの到達確認のみ済みで、内容の確認と確定は利用者が行う。
- 確定したら SKILL.md の見出しと注意書きを更新する。

## release-notes

設定ファイルに登録したサービスの最新のリリースノートを、公式ページから集めてまとめる。
既定のサービスは Claude、ChatGPT、Gemini（アプリ・製品の更新。API・開発者向けは対象外）。
research-collector で収集し、research-checker で日付・出典・内容を裏取りする。
手動で呼んだときだけ動く。定期実行はしない。

使い方：/release-notes [期間] [サービス名]

- 既定の期間：前回の成果物以降（前回がなければ直近2週間）
- 既定のサービス：設定で enabled が true のすべて。サービス名を指定すると絞り込める（例：Claude,Gemini）
- 項目数の上限：1サービスあたり10件（仮）。引数で変更できる

設定ファイル：config/release-notes.json（Git管理対象）

- services の各サービスに、name、enabled、sources（label と url）を書く。
- サービスを増やすときは、services に書き足す。使わないサービスは、enabled を false にする。
- 情報源のURLは、実在とアクセスを確認したものだけを書く。source_list_status は「暫定」。

出力

- outputs/research/yyyymmdd_release-notes/topic_summary.md
- サービスごとにまとめ、見出し一覧、結論、使用したエージェント、根拠、参考サイトを載せる
- 過去の outputs/research/*_release-notes/ を確認し、掲載済みの項目は重複して載せない

取得についての注意

- 1つの情報源につき、取得は原則1回。連続・並列の取得はしない。
- 取得できなかった情報源は「更新なし」と扱わず、取得状況に書く。
- 公式サイトの利用規約に、自動での取得を禁じる記載があるサービスがある（Claude、OpenAI。公開ページの閲覧への適用は未確認）。呼んだときだけ、必要最小限の回数で取得する。
- Gemini は、地域・言語で掲載内容が異なる。設定は US・英語版にしている。

## convert-post

Markdown のファイルを、貼り付け先（WordPress の Cocoon、Confluence など）に合わせた装飾済みの形式に変換する。
変換先は実行時に選ぶ（引数で指定、または一覧から選択）。エージェントは使わない。

使い方：/convert-post [変換先] [元のmdファイルのパス]

- 元のファイルは、任意のmdファイルでよい。
- 変換するのは見た目の装飾だけで、文章の内容は変えない（元にない情報は足さない）。
- 変換先ごとのルールは、.claude/skills/convert-post/targets/ にファイルとして置く。変換先を増やすときは、ここにファイルを足す。
- 貼り付けるだけで使える装飾だけを使う。貼り付けたあとに手作業が必要な装飾は使わない。
- 現在の変換先：cocoon（HTML）、confluence（Markdown + 絵文字）

出力

- outputs/convert/yyyymmdd_topic/ に、変換後のファイル（post_cocoon.html など）だけを保存する。
- 貼り付け方は、完了時の報告で伝える（ルールの「貼り付け方」に書いてある）。

変換先ルールの状態

- 変換先ルールは「暫定」。公式のソースやドキュメントで確認できた記法だけを使っているが、実際に貼って表示を確認するまで「検証済み」にしない。
- Confluence は、パネルや展開など、貼り付けでは作れない装飾は使わず、引用・太字・区切り線・絵文字で装飾する。
