# 改善履歴

AI組織の役割、判断基準、運用方法を変更した際は、変更内容とその理由を記録する。

## 2026-11-27

ビューアの目次を、すべての成果物に拡大

- 内容：「成果物」タブで、記事風表示の対象外のmdにも、見出し（##、###）から作った目次を右側に出すようにした。見出しが3つ未満なら付けない。docs/viewer.md を更新した。
- 理由：長い成果物でも、目次から目的の項目へ移動できるようにするため。
- 補足：変更は apps/viewer/index.html の1か所のみ。ニュースとリリースノートの表示は変更していない。反映にはブラウザの再読み込み（Ctrl+F5）が必要な場合がある。依存関係の追加はない。

## 2026-11-26

release-notes の対象サービスに Snowflake と dbt を追加

- 内容：config/release-notes.json に Snowflake（サーバーのリリースノートと機能更新）と dbt（dbt リリースノート）を追加した。docs/skills.md と README を更新した。
- 理由：データ基盤まわりの更新も、AIサービスと同じ流れでまとめて把握するため。
- 補足：URLは、到達（HTTP 200）と robots.txt（取得を妨げる記載なし）を確認した。dbt の利用規約に自動取得を禁じる記載は見当たらなかった。Snowflake の利用規約ページは 403 で読めず、未確認。情報源リストは「暫定」のまま。Snowflake のプレビュー機能・クライアントのページは対象外。依存関係の追加はない。

ビューアの装飾の拡張（リリースノート、ヘルプ）

- 内容：リリースノートを、IT・セキュリティニュースと同じ記事風の表示（サービス別の目次、項目の展開・縮小、サービス・確認状況・日付のタグ）にした。ヘルプの文書には、見出しから作った目次を右側に出すようにした。release-notes の成果物形式に「- 確認:」の行を足した。docs/viewer.md を更新した。
- 理由：ITニュースと同様に、長い成果物や文書を、目次から目的の項目へ移動しながら読めるようにするため。
- 補足：変更は apps/viewer/index.html のみで、サーバーと既存の成果物は変更していない。「- 確認:」の行がない過去の成果物でも表示はできる（確認状況のタグは付かない）。画面の変更後は、ブラウザの再読み込み（Ctrl+F5）が必要な場合がある。依存関係の追加はない。

リリースノート収集スキル（release-notes）の追加

- 内容：設定ファイル（config/release-notes.json）に登録したサービスの、最新のリリースノートを公式ページから集める /release-notes を追加した。既定のサービスは Claude、ChatGPT、Gemini（アプリ・製品の更新）。期間の既定値は「前回の成果物以降」。収集は research-collector、裏取りは research-checker で行い、outputs/research/yyyymmdd_release-notes/topic_summary.md に保存する。docs/skills.md と README を更新した。
- 理由：複数のAIサービスの更新を、サイトを巡回せずにまとめて把握するため。サービスを増やすときは、設定ファイルに書き足すだけで済むようにした。
- 補足：情報源のURLは、実在と到達（HTTP 200）、robots.txt を確認したもので、状態は「暫定」。Claude と OpenAI の利用規約には自動取得を禁じる記載があるため（公開ページの閲覧への適用は未確認）、呼んだときだけ、1情報源につき原則1回の取得にしている。Gemini は地域・言語で掲載内容が異なるため、US・英語版を使う。API・開発者向けのリリースノートは対象外。依存関係の追加はない。

Markdown の変換スキル（convert-post）の追加

- 内容：Markdown を、貼り付け先（WordPress の Cocoon、Confluence など）に合わせた装飾済みの形式へ変換する /convert-post を追加した。変換先は実行時に選ぶ。変換先ごとのルールは、.claude/skills/convert-post/targets/ に置く（現在は cocoon と confluence）。変換結果は outputs/convert/yyyymmdd_topic/ に、変換後のファイルだけを保存する。CLAUDE.md の成果物ルールに、カテゴリ convert（topic_summary.md の例外）を追加した。docs/skills.md と README を更新した。
- 理由：調査や議論の成果物を、社内のWiki（Confluence）やブログ（Cocoon）にそのまま貼れる形で、見栄え良く使えるようにするため。貼り付け先ごとに記法が違うため、変換先を分けた。
- 補足：変換先のルールは、research-collector で調べ、research-checker で裏取りした確認済みの記法だけで作った（状態は「暫定」）。実際に貼って表示を確認するまで「検証済み」にしない。貼り付けたあとに手作業が必要な装飾は使わない方針にした。Confluence は、パネルや展開などを使わず、引用・太字・区切り線・絵文字で装飾する。Cocoon は、アイコンの登録が必要な吹き出しを使わない。依存関係の追加はない。

research-it-news の調整（ビューアでの表示に合わせる）

- 内容：見出しの「未確認:」の接頭辞をやめ、理由は「未確認の点」の行に書くようにした。各項目に「重要度」（高・中・低）と「カテゴリ」（脆弱性・インシデント・クラウド・その他）の行を足し、出典の日付を yyyy-mm-dd で書くようにした。項目数の上限の既定値を20件から10件にした。docs/skills.md を更新した。
- 理由：未確認の多くは「深く確認していないだけ」で、見出しの接頭辞が実態より悪い印象を与えていたため。重要度とカテゴリは、ビューアの記事風の表示でタグとして使う。
- 補足：「確認済み」と「未確認・続報待ち」のセクション分けは維持した。上限が10件になり、全項目が一次情報まで確認される形になる（裏取りの時間とトークンは増える見込み）。過去の成果物は書き換えていない。

ビューアの改良

- 内容：タブを「成果物」「ツール」「ヘルプ」の3つに整理した（ツールに一問一答と作業ログをまとめた）。ヘルプタブで README.md、CLAUDE.md、docs/ を閲覧できるようにした。成果物・ヘルプの検索窓で、ファイル名・タイトル・本文を検索できるようにした。IT・セキュリティニュースは、記事風の表示（タグ、項目の展開・縮小、別枠の目次）にした。docs/viewer.md を更新した。
- 理由：設定や説明も同じ画面で読めるようにし、機能が増えたタブを整理するため。ニュースを、ブログ記事のように読みやすくするため。
- 補足：サーバーに /api/doc、/api/docs、/api/search を追加した。返すファイルは、outputs/ 配下の .md、README.md、CLAUDE.md、docs/ 配下の .md に限定している。画面の変更後は、ブラウザの再読み込み（Ctrl+F5）が必要な場合がある。依存関係の追加はない。

一問一答の問題集（mentor-question）の追加

- 内容：ノートから一問一答の問題集を作る /mentor-question を追加した。ビューアに「一問一答」タブを追加し、1問ずつ解けるようにした。
  問題集は outputs/mentor/quiz/questions/ に保存する。docs/mentor.md、docs/viewer.md、docs/skills.md、README を更新した。
- 理由：対話式の出題だけでなく、ブラウザで気軽に繰り返し解ける形式が欲しいため。
- 補足：既存の /mentor-quiz は変更していない。正誤の記録は保存しない。依存関係の追加はない。

ローカル閲覧ビューアの追加

- 内容：outputs/ の成果物（Markdown）と logs/ の作業ログをブラウザで閲覧するビューアを追加した（apps/viewer/）。
  start-viewer.bat / start-viewer.command で起動する。詳細は docs/viewer.md。README、docs/setup.md、docs/agents.md を更新した。
- 理由：成果物やログをエディタで探さず、一覧から読めるようにするため。
- 補足：Python標準ライブラリのみで、依存関係の追加はない。127.0.0.1 にのみバインドし、閲覧専用にしている。

## 2026-11-19

作業ログの保存形式を .md から .txt に変更

- 内容：保存先を logs/yyyymmdd_workLog.txt にした（CLAUDE.md、docs/worklog.md を更新）。
- 理由：記録は1行のテキストで、Markdownの記法を使わないため。拡張子と中身を一致させ、Windowsでメモ帳などで開けるようにするため。
- 補足：config/worklog.json の `True` を `true` に修正（JSONとして正しくなるように）。

作業ログの設定ファイル化

- 内容：依頼ごとの作業ログを、config/worklog.json の `work_log_enabled` で設定できるようにした。
  詳細は docs/worklog.md。CLAUDE.md（6.作業ログ）、README、docs/setup.md から参照する。
- 理由：ログの記録を人間が設定ファイルで切り替えられるようにするため。
  フラグファイルより、設定の意味と場所が分かりやすいため。

配布準備

- 内容：LICENSE（MIT）と docs/setup.md（前提条件、言語、モデル設定、共通ルールの注意）を追加し、
  README に前提の一行と docs/setup.md への案内を追記した。
- 理由：他人に配布できる形にするため。READMEは短く保ち、詳細は docs/ に置いた。

メンターの統合

- 内容：別リポジトリで運用していたメンターを統合した。
  メンターはエージェントではなく /mentor スキルとし、mentor-note / mentor-quiz /
  mentor-organizer / mentor-review を .claude/skills/ に移した。
  保存先は output/ から outputs/mentor/（notes / quiz / review）に変更した。
- 理由：本リポジトリを様々なエージェントをまとめる場所にするため。
  常時メンター化する設定（CLAUDE.md）は、司令塔のルールと干渉し、起動時の読み込みも増えるため、
  取り込まず、呼んだときだけ動くスキルにした。CLAUDE.md は共通ルールだけを保つ。
- 補足：/mentor は disable-model-invocation で手動呼び出し専用にした。
  outputs/mentor/ の中身は個人的な内容のためGit管理外とし、.gitkeep のみ管理する。
  旧CLAUDE.mdの「記録のルール」は、各スキルと /mentor に分けて移した。

research-it-news の追加

- 内容：IT・セキュリティニュースを、情報源リストから収集・裏取り・要約するスキルを追加した。
  既存の research-collector と research-checker を使い、新しいエージェントは作っていない。
  手動呼び出し専用で、期間とテーマを指定できる。
- 理由：ニュース収集を、毎回の検索任せにせず、同じ型で繰り返せるようにするため。
  情報源リストは暫定で、利用者の確認後に確定する。

research-it-news の調整（初回実行を受けて）

- 内容：項目数の上限（仮20件）、裏取りの深さの段階化（上位は一次情報まで、下位は出典・日付まで）、
  全情報源の取得結果の報告、curl での再試行、相手サーバーへの配慮（連続・並列アクセスの抑制、
  robots.txt と利用規約の確認）を SKILL.md と skills.md に追記した。
- 理由：初回実行で、エージェント合計が約30万トークン・約10分かかり、
  一部の情報源（JavaScript 描画、アクセス拒否）が取得できなかったため。
  取得できなかった情報源を「更新なし」と誤解しないようにする狙いもある。
- 補足：RSS や API の情報源は、実在確認と利用者の確定がまだのため、リストには追加していない。

モデル設定の変更

- 内容：research-checker と critic の model を inherit から opus に変更した。
  research-collector、realist、idealist は inherit のまま。
- 理由：裏取りと批判は、判断や検証の精度が重要なため。
- 補足：opus はモデルの別名。使えるモデルは環境で異なるため、変更方法は agents.md に記載した。

ドキュメントの整理

- 内容：README を目的・使い方・一覧・運用のコツ・docs/ への案内に絞り、
  詳細を docs/（agents / skills / mentor / changelog）に移した。
  旧 README の内容（フォルダ構成、命名方針、運用方針、拡張候補）は agents.md に移した。
- 理由：README を短く保ち、詳細を必要なときだけ読めるようにするため。
