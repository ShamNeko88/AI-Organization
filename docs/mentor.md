# メンター

勉強や業務の相談に乗ってもらいながら、その過程を学習ノートとして記録する。
ノートは、後の復習・問題作成・振り返りの材料になる。

流れ：相談・支援 → 学習ノート作成 → 問題作成 → 振り返り

## スキル

- /mentor：メンターとして応答する。呼んだときだけ有効。「メンター終了」で通常の応答に戻る
- /mentor-note：相談内容を学習ノートにまとめて保存する
- /mentor-quiz：カテゴリのノートから問題を作り、1問ずつ対話式で出題する
- /mentor-organizer：「その他」のノートを整理し、新しいカテゴリフォルダを提案する
- /mentor-review：指定した期間のノートを要約し、振り返りを作る

## 使い方

1. 本リポジトリでClaude Codeを起動し、/mentor を実行する。
2. 勉強や業務の相談をする。
3. 区切りのよいところで /mentor-note を実行する。
   → outputs/mentor/notes/<カテゴリ>/yyyymmdd_テーマ.md に保存される。
4. 復習したいときは「/mentor-quiz カテゴリ名」のように指定して実行する。
5. 期間ごとに振り返りたいときは /mentor-review を実行する。（期間は実行時に確認される）
6. 終わるときは「メンター終了」と伝える。

## 応答の深さ

トークン消費を抑え、記録だけのチャットを邪魔しないため、応答は使い分けられる。

- 詳しく答える（明確な依頼があったときだけ）
  「教えて」「〜って何？」「〜について説明して」「〜についてまとめて」「問題を出して」「分からない」
- 一言で受け取る（上記以外）
  「今日は〇〇をやった」などの報告や記録。解説、確認質問、提案はされない。
- 迷う発言
  「解説しますか？」と聞かれる。

## 保存の確認

保存し忘れを防ぐため、次のタイミングで「ここまでをノートにまとめますか？」と聞かれる。

- 話題が一区切りついたとき
- 「ありがとう」「今日はここまで」など、終わりそうな発言をしたとき
- まとめていないまま、同じ話題で長くやり取りしたとき

断ると、同じ話題ではしばらく聞き直されない。「はい」と答えると、そのままノートが作成される。

ノートの内容：目的・分類（勉強/業務）・タグ、学んだこと・決まったこと、つまずいた点、
残っている疑問・次にやること、復習・問題作成用メモ。

## クイズ

「/mentor-quiz カテゴリ名」のように、カテゴリフォルダを指定して実行する。

- 出題前に、カテゴリと出題数を確認される。
- ノートの「復習・問題作成用メモ」などから問題が作られ、1問ずつ出題・採点される。
- 結果は outputs/mentor/quiz/yyyymmdd_カテゴリ.md に保存される。

## 振り返り

/mentor-review を実行すると、期間内のノートの要約を作る。

- 実行のたびに、振り返る期間（開始日と終了日）を確認される。
- 全カテゴリのノートから、ファイル名の日付が期間内のものが対象。
- 結果は outputs/mentor/review/yyyymmdd-yyyymmdd.md（開始日-終了日）に保存される。

## 「その他」の整理

「その他」にノートがたまってきたら、/mentor-organizer で整理する。

- 似た内容のノートが3件以上あるグループを、新しいカテゴリフォルダとして提案する。（3件は仮の基準）
- フォルダの作成とノートの移動は、承認した分だけ行われる。ノートの内容やファイル名は変わらない。

## フォルダ構成

```text
outputs/mentor/
├── review/                 # 振り返り（yyyymmdd-yyyymmdd.md）
├── quiz/                   # クイズ記録（yyyymmdd_カテゴリ.md）
└── notes/                  # 学習ノート
    ├── README.md           # カテゴリ一覧と一行の説明
    ├── <カテゴリ>/         # 技術分野ごとのフォルダ
    │   └── yyyymmdd_テーマ.md
    └── その他/             # どのカテゴリにも当てはまらないノート
```

- カテゴリは技術分野で分ける。勉強/業務の区別はフォルダではなくタグで行う。
- 複数のカテゴリにまたがるノートは、主なカテゴリのフォルダに保存し、他のカテゴリはタグに入れる。
- 新しいカテゴリフォルダを作る前には確認される。作ったあとは、notes/README.md に説明が追記される。
- ルールや形式を変えたいときは、.claude/skills/ 内の各 SKILL.md を編集する。
  （例：ノートの形式は mentor-note/SKILL.md）

## 注意点

- 記録していない相談は残らない。
  Claudeはセッションをまたいで会話を覚えていない。/clear や終了の前に /mentor-note を実行する。
- 機密情報を書かない。
  APIキー、パスワード、個人情報、業務上の機密情報はノートに入れない。
- outputs/mentor/ の中身はGitに保存されない。
  .gitignore で無視される（空フォルダ維持用の .gitkeep のみ管理）。
  バックアップは別途取る。別の環境では、outputs/mentor/ フォルダごとコピーすれば引き継げる。
- ノートは保存後に目を通す。
  会話から自動でまとめるため、誤解や抜けがあるかもしれない。
- 同名ファイルは上書きされない。追記か別名かを確認される。
- PCのClaude Codeで使う前提。（スマホは想定していない）
